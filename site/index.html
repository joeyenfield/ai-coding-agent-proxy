What is AI Control Mesh?

The layer between your
coding agents and your AI.

AI Control Mesh is a self-hosted server, a web console, and lightweight programs for the computers in your organization. Together, they connect the tools people use to the models, machines, and shared tools your team provides.

Keep using coding agents such as Claude Code, Codex, GitHub Copilot CLI, Qwen Code, OpenCode, Aider, and Goose. Launch supported agents through the mesh to record their model traffic, choose a compatible provider, and optionally share their terminal.

A control plane, not another model

It does not train a model or replace your coding agent. It gives you a shared place to route requests, inspect activity, manage model infrastructure, and decide who can use it.

Inside the mesh

One hub.
Three distinct roles.

A developer’s laptop runs the client. A model host joins the fleet. Your server coordinates both. A single computer can fill more than one role.

The server coordinates. It asks a fleet machine to manage its models, containers, and tools; it does not run those workloads itself.

The machine executes. Model management and remote launches happen on the selected machine, subject to its enabled features and access grants.

Follow one request

From a coding task
to a visible session.

Here is the path for an agent using a local model. Replies stream back along the same route while the server records the request.

Local models

Use infrastructure you own

Send supported agents to compatible Ollama, Strata, or Docker Model Runner backends. Ollama requests are translated and tuned; native-compatible backends receive pass-through traffic.

Hosted APIs

Keep a hosted provider

Route supported hosted API traffic through the server and record it alongside your local-model sessions. The provider still receives and processes those requests.

Agent accounts

Keep the agent’s own service

Supported account agents continue talking to their vendor. Their HTTPS is captured using a server-managed certificate authority trusted by the launched process tree—not redirected to a local model.

Provider compatibility depends on the agent and protocol. Local routing does not make an agent offline, and hosted or account traffic still leaves your infrastructure.

Share access deliberately

Accounts belong to organizations and teams. Session visibility and permission to type are separate choices. Machine grants control features such as launches, terminals, model management, and MCP access.

Your infrastructure, your responsibility

Remote launches and terminals can run commands. Machines must opt in and restrict project roots. Captured prompts and replies can contain sensitive data: protect the server, use HTTPS, and choose what you record and share.
