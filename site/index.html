01 / Run it locally

Your first mesh,
on your computer.

Start the server and console, OIDC sign-in, PostgreSQL, two fleet machines, and Ollama. The images are pulled from the project’s published container registry.

Bring: Git, Docker with Compose or Podman with a Compose provider, several GB of disk, and free localhost ports 19999 and 20000. Allow at least 8 GB RAM for a small CPU-model trial; model size and context can need much more. On Windows/macOS, allocate that memory to the container VM. A GPU is optional; CPU speed varies.

Follow the guided quickstart →
LOCAL DEMO / TERMINAL
git clone https://github.com/joeyenfield/ai-coding-agent-proxy.git
cd ai-coding-agent-proxy
docker compose -f quickstart/compose.yaml up -d
Podman instructions

Use the same clone and folder commands above, then:

podman compose -f quickstart/compose.yaml up -d

Requires a Compose provider (podman compose version). On Windows/macOS: podman machine init once, then podman machine start.

  1. Open localhost:19999 (use localhost exactly). Sign in with admin / secret.
  2. In Machines → machine-1 → Model servers, choose Ollama and Add as a provider. Use Find and pull to download a small, tool-capable model. No model is downloaded automatically.
  3. In machine-1’s Agents → Start an agent, pick OpenCode or Qwen Code, provider machine-1, your downloaded model and folder /workspace. Enable Capture full request and response payloads for this trial, then start.
  4. In the terminal, send “Write a Python script that prints the first ten primes.” Follow Requests for tokens and timings, then Sessions → Chat for the recorded conversation.

Local demo only. Uses known credentials and ports bound to 127.0.0.1. Keep it on your computer; changing the admin password alone does not make it a production install. For a real deployment, configure your own secrets, HTTPS, and sign-in service. Team deployment path →

Compatibility: agents, providers and account capture

These are the shipped integration routes. A supported protocol is not a guarantee that every agent version, model or tool call will work well. Validate your chosen combination.

1. Local-model agents and provider compatibility

* Docker Model Runner integration is implemented but verified here against mocks, not a real Model Runner: treat it as experimental for evaluation. † Codex needs Ollama’s Responses support; per-request Ollama tuning is not applied on this route. Set context on the model server. llama.cpp uses llama-server in router mode.

2. Hosted API forwarding

claude-subscription forwards Claude Code’s Anthropic API calls using the agent’s own credentials. Other traffic, such as OAuth and telemetry, can go directly to the vendor. This is not a general gateway for every cloud API.

3. Vendor-account capture

claude-account, codex-account and copilot-account keep using their vendor services. The server decrypts permitted proxied traffic using a CA trusted by the launched process tree. Review that trust boundary.

Local model routing does not make the whole agent offline. Agents and tools can still contact external services. MCP support also varies: Aider cannot attach shared MCP servers. Agent setup → · Provider reference →
