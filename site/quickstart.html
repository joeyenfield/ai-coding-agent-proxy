Quickstart / On your computer

Your first mesh,
in ten minutes.

Start the server, its sign-in service, PostgreSQL, two fleet machines and Ollama on your own computer. Then add a provider, pull a model and start a coding agent on it. Every screenshot below is the real quickstart, started fresh.

1 / Start it

One command.

Pick how you run containers, and whether models run on the CPU or an NVIDIA GPU, then run the commands from any folder. The images are pulled from the project’s published container registry.

Bring: Git, Docker with Compose or Podman with a Compose provider, several GB of disk, and free localhost ports 19999 and 20000. Allow at least 8 GB RAM for a small CPU-model trial; model size and context can need much more. On Windows/macOS, allocate that memory to the container VM. An NVIDIA GPU is optional and makes models much faster (choose NVIDIA GPU above the commands); on CPU, speed varies.

Podman needs a Compose provider (podman compose version). On Windows and macOS, run podman machine init once, then podman machine start.

For a cluster on your computer: kind, k3d, minikube, or the one in Docker, Rancher or Podman Desktop, with a default StorageClass, kubectl and Helm 3. Keep the release name mesh. It installs the chart in its smallest form (one pod: the server and its sign-in service, SQLite on a volume) and a fleet machine with the coding agents and Ollama. When both pods are running, forward the ports in a terminal you leave open:

kubectl -n mesh port-forward svc/mesh-agent-mesh 19999:19999 &
kubectl -n mesh port-forward svc/mesh-agent-mesh-auth 20000:20000

Then open localhost:19999. The admin password is in the server’s log (kubectl -n mesh logs deploy/mesh-agent-mesh -c agent-server | grep -i password), and the machine signs in with two device codes from its log, approved on Machines › Approve a device. Kubernetes quickstart → For production (HTTPS host names, PostgreSQL, a Deployment per role): the chart’s README →

The Kubernetes quickstart runs Ollama on the CPU. To give it a GPU, add a nvidia.com/gpu: 1 limit to the ollama container in deploy/helm/quickstart/machine.yaml; the cluster needs the NVIDIA device plugin.

The GPU file gives Ollama your NVIDIA GPUs, so models answer much faster. Use it every time you start the stack; without it, Ollama runs on the CPU. Docker needs the NVIDIA Container Toolkit with CDI on. With Podman, check it sees the GPU first: podman run --rm --device nvidia.com/gpu=all docker.io/library/ubuntu:24.04 nvidia-smi. GPU setup →

Local demo only. Uses known credentials and ports bound to 127.0.0.1. Keep it on your computer; changing the admin password alone does not make it a production install. For a real deployment, configure your own secrets, HTTPS, and sign-in service. Team deployment path →

Or / Without a checkout

Two shorter ways in.

Both run on your own computer, on localhost only, with the same console on localhost:19999. They make their own admin password and print it.

One container

The whole system in a single container: the server, sign-in, the console and a fleet machine with the coding agents and Ollama. Needs Docker or Podman, and no Git.

docker run -d --name mesh \
  -p 127.0.0.1:19999:19999 -p 127.0.0.1:20000:20000 \
  -v mesh-data:/data -v mesh-home:/home/agent \
  -v mesh-workspace:/workspace \
  ghcr.io/joeyenfield/ai-control-mesh
docker logs mesh

docker logs prints the address and the password. With Podman, write podman for docker. One container, in the guide →

No containers

One command installs the server, agent and agent-machine for you alone and starts them, with an icon in the system tray. Needs Python 3.11 or later.

curl -fsSL https://github.com/joeyenfield/ai-control-mesh/releases/latest/download/install-local.sh | sh
irm https://github.com/joeyenfield/ai-control-mesh/releases/latest/download/install-local.ps1 | iex

The first is for Linux, macOS and FreeBSD, the second for Windows PowerShell. Every download is checked against its SHA-256, and uninstall-local from the same address removes it again. Run it on your own computer →

2 / Step by step

From sign-in to an answer.

When all six containers are healthy (compose ps), the first start takes a few minutes, follow these in the console.

  1. 1Sign in

    Open localhost:19999. Type localhost exactly: sign-in only accepts that address. Continue to sign in takes you to the sign-in service on port 20000.

    Sign in as admin with the password secret. You come straight back to the console, which never sees your password.

  2. 2Check the machines

    Open All machines. machine-1 and machine-2 are already Online: they signed themselves in when they started, so there's nothing to approve. Both take agents and terminals; machine-1 also shares its Ollama.

  3. 3Add machine-1's Ollama as a provider

    Model servers belong to the machines that run them, and an admin adds each one once. On machine-1, open Providers: it found Ollama on port 11434, Not a provider yet.

    Open it and choose Add as a provider. Agents on either machine can now use it, through the server and machine-1's own connection: no port to publish.

  4. 4Find a model and pull it

    Ollama starts empty, and nothing downloads by itself. Open Find and pull, keep Ollama library, search for qwen3.

    Each family lists its sizes; tools is what coding agents need. On a CPU, pick something small: Pull 1.7b downloads 1.3 GB and answers in seconds.

    When it's done, it's on the Models tab, with the settings the server uses for it.

  5. 5Start Qwen Code on machine-1

    Choose Start an agent. Pick machine-1 and Qwen Code; the provider, the /workspace folder and your model are filled in. Choose Start on machine-1.

    It starts in a terminal shared with the server, and the console opens it: watch it and type into it from any device.

  6. 6Ask it something

    Type What model are you? in Message for the agent and choose Send. The first answer is the slowest: Ollama loads the model on the first request, a minute or two on a CPU.

  7. 7See what it sent

    Requests has every request the agent made: model, provider, time and tokens. Select one for the full request, the reply and the payload sent to Ollama. The first one here timed out while the model loaded, and Qwen Code asked again.

3 / Then

Keep going.

Give it a task

Send write a Python script that prints the first ten primes and watch it work. Live shows each model request as it streams; Running agents shows which agents are working or waiting for you.

Read it back

Sessions has one row per agent run, with a Chat view when capture is on. Traffic groups requests by what they were for.

Stop, reset or troubleshoot

compose down stops it and keeps your data; down -v deletes it too. The guide lists what to check when something doesn’t start.
